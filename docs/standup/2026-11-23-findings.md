## 3. Lessons from three days of real stand-ups

1. **The user's own account wins.** On 2026-11-19 the user said "you will find
   nothing in here … do not search here and there" for work done outside any
   repo. Evidence confirms what they said and fills gaps. It doesn't overrule
   them. If they say "today is only X", the other open tickets go under
   **Left** as moved.
2. **The question set belongs to the profile.** The team's stand-up bot asks
   Yesterday, Today, **Left, Blocked**, Other, which is a different order from
   the original request. Question wording and order have to be stored per
   profile.
3. **Never write to the tracker, comments included.** The tracker connector
   was signed in as a teammate, so a comment would have shown up as theirs. The
   draft carries the comment text, and the user pastes it.
4. **A late ticket still gets a Today line.** A reviewer sent back a "Today:
   late" line. Today says what will be done on the ticket today. The lateness
   and the new date go under **Left**.
5. **A late ticket must match the tracker before posting.** The due date gets
   moved and a short comment says why it slipped. The reviewer checks this.
   The skill lists the mismatch and drafts the comment, and the user acts on it.
6. **On a team profile, work with no ticket is left out**, for example admin
   clean-up.
7. **Other must not repeat Yesterday.** A meeting that approved a ticket is
   that ticket's Yesterday line. When a duration isn't known, ask. Never guess.
8. **Style:** bold question headers, `•` bullets, one line each, plain words,
   no file paths or internal jargon. A missing ticket id is written `XXX-___`
   and flagged.
9. **A report can change after it is posted.** On 2026-11-23 the reviewer
   asked for two fixes. The saved file kept the final "As posted" text, a
   "Fixes" note and a "Sources checked" list.
10. **Time zone matters.** Session timestamps are UTC, and "yesterday" is a
    local working day.
11. **The log folder in use is `<profile>/standups/YYYY-MM-DD.md`**, not the
    `.status/` folder from the spec.
12. **Project to-do files are evidence too.** One repo keeps a daily to-do
    file with `[x]` items.

## 4. Where the 2026-11-18 spec and practice disagree

| Topic | Spec | Practice | Resolution in the new spec |
|---|---|---|---|
| Log folder | `<profile>/.status/`, its own git repo | `<profile>/standups/`, plain files | one fixed `~/standups/` for every report, with the path computed by the script; no nested git repo (user's call, D2) |
| Question order | fixed at five | per profile | stored per profile |
| Source priority | evidence first | user's account first | user's account first |
| Tracker writes | none; offers "ticket-update" | none, and the draft carries comment text | none; drafts the text; names no other skill |
| Late tickets | status only in Left | Today line plus Left; tracker must match | both |
| Saved file | approved text plus JSON | As posted, Fixes, Sources checked | all of these, plus the JSON sidecar |
| Names | real client, team and channel names in the spec | n/a | spec and skill fully generic |

## 5. Repo notes for adding the skill

- **Shipping needs a version bump.** The plugin cache is keyed by version
  (`0.2.0`), so a new skill folder with no bump never reaches an installed
  machine. Shipping it touches `plugin.json`, the marketplace description and
  the README's skill table: four lines outside the new folder. No other skill
  file changes.
- **The old spec breaks the repo's own rules for skills.** It tells the skill
  to "offer to run `ticket-update`", but no skill may name another one. It also
  names a real client, team and channel in a public repo. The new spec fixes
  both.
- **`ticket-update`'s description says "write my stand-up line".** That means
  a one-line status after a ticket change, which is a different request from a
  full stand-up. Both stay. The new skill's description is worded for full
  reports and pasted bot prompts.
- **The remote-sync `CLAUDE.md`** ("commit and push after every unit of work")
  exists only on the side branches, not on `main`.
- `docs/**/private/` is gitignored, so the session-evidence file that quotes
  client work is not published. Good.
