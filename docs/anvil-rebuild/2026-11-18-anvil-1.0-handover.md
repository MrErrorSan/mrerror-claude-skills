## What shipped

A self-contained Anvil plugin (`plugins/anvil`, version 1.0.0) with no Superpowers dependency:

- **Skills (12):** `anvil` (router), `brainstorm` (writes the spec; no separate `spec` skill), `plan`, `build`, `verify`, `finish`, `debug`, revised `afk`, `ticket-update` (plan → ticket mapping), and `cross-model`, `ui-mockup`, `ux-audit`. The last two got interim fixes only: local mock files, no auto-implement, findings returned rather than applied. Their full rewrite is phase 3.
- **CLI `bin/anvil`** (Python ≥ 3.10, standard library): topics and stages, gates (`present`/`approve`/`check`, pre-approval, AFK), `spec-lines`, `stale`, `plan-check`, `lane-check`, `run`/`fresh` result reuse (scopes `targeted|full|smoke|check`), `progress`, and the hook entry point.
- **Hooks (4):**
  - **SessionStart** states plain facts.
  - **UserPromptSubmit** logs your messages. It skips turns Claude Code starts itself, such as subagent reports.
  - **PreToolUse** does three things:
    - holds repo edits outside the topic folder until the plan is approved;
    - denies hand-written `Approved:` lines;
    - answers a test command from a fresh green result instead of rerunning it.
  - **Stop** keeps an AFK run going.
- **Shared formats** in `plugins/anvil/references/` (formats, test policy, git flow, simplicity).
- **Evals:** 9 plugin-eval cases in `plugins/anvil/evals/`.
- **Upstream watch:** `upstream/superpowers/` holds the runbook, baseline, source map, decision ledger, provenance and tools. There's also a project skill, `superpowers-upstream`, and `docs/anvil-principles.md` (P1–P44, your decisions).
- **Packaging:** `plugin.json` 1.0.0 with no dependencies, the marketplace without the cross-marketplace allowance, a new README, and the `NOTICE` (Superpowers MIT).

## Decisions most worth your review

From the decision log, the ones that most deserve a look:

1. **Pre-approval window.** `--pre` accepts only your words from the request that started the topic onward. My first ruling (any logged prompt) was overturned in the final review.
2. **The PreToolUse hold doesn't gate agent dispatch.** Brainstorm needs subagents before stop 2. It holds repo edits outside the topic folder instead, and that hold applies inside subagents too. Bash writes aren't held. Design §7.2 and §12.3 still say "blocks agent dispatch"; worth rewording the design to match.
3. **In AFK, verify lands the last commit point,** because `finish` can't be model-invoked. The last commit point is recorded as `- C<k> (this commit) <date>`, so it stays one squash.
4. **Lane worktrees are created by the orchestrator,** not by `isolation: "worktree"`. A lane cut before a commit point is cherry-picked, not merged; this build hit that once.
5. **`topic start` refuses a different slug** while a topic is active. Unrelated work parks the topic with `topic end`.

## Weakest part

The behaviour of the skills hasn't been measured. It has only been reviewed by reading.

- Every check so far is structural: unit tests, lint, validators, and reviewers tracing the text.
- Whether a model actually follows the flow the same way every time (design goal 1) needs the evals and the skill-creator runs (items 1 and 2).
- The AFK path is the least exercised. It got the most review fixes.
