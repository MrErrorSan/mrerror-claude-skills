# Anvil V2: plan

- **Date:** 2026-11-19.
- **Branch:** `anvil-v2`, cut from `anvil-rebuild`.
- **V1 baseline:** tag `anvil-v1.0`, measured in [../anvil-ab/2026-11-18-ab-results.md](../anvil-ab/2026-11-18-ab-results.md).
- **Rule:** V2 ships only if the same A/B suite shows it at least as good as V1 on correctness and judge score, and clearly faster.
- **What stays (Saad's decisions):**
  - the size line in the first reply;
  - stop 1 and stop 2, which pass only on Saad's words;
  - the spec and plan documents and the decision log;
  - no co-author trailers;
  - project rules win;
  - AFK logging.

## Changes

Each change cites the finding in the results doc (§3, F-numbers).

| # | Change | Where | Evidence | Expected effect |
|---|---|---|---|---|
| V2-1 | **Inline by default for small plans.** For 3 tasks or fewer, sequential, the orchestrator builds the tasks itself. There's no implementer subagent, no per-task review and no re-review. Then one fresh reviewer (mid tier) reviews the whole diff, spec first, then quality. One fix round. A re-review only when the fix touched files outside the findings. | build, plan | F1, F4: a median of 7 subagents and 355 s waiting on them, plus 474 s of orchestration, on 14–75-line changes | c2, c3, c6, c7 drop from 5–17 min toward 2–4 min |
| V2-2 | **Fewer review rounds in subagent mode.** The final whole-branch review only runs for 4+ tasks or a 300+-line diff. A scoped re-review only when a fix went beyond its findings; otherwise lane-check plus the targeted test. | build | F1: re-reviews of 1-line fixes (c3-A-r1: 74 s for a one-token fix) | Fewer serial subagent rounds on larger plans |
| V2-3 | **Verify lands the work.** In every mode, verify squashes the last commit point onto the synced branch (local; it pushes only if the plan's row says so), resets the work branch, and leaves the topic at stage `finish`. `/anvil:finish` becomes optional: push, merge, PR, ticket, branch clean-up. `topic start` for new work auto-parks a topic already at `finish`. | verify, finish, router, CLI `topic start` | F2: 14/14 runs ended asking for `/anvil:finish`, 11 user turns were spent declining it, and 10/14 feature branches held no code | The code is on the synced branch at hand-off; no extra turn |
| V2-4 | **AFK keeps going.** Under AFK, never ask Saad to run a command. "Keep going" after delivery means fixing the cheap, in-scope deferred items already listed, then reporting. | afk | F3: c7-A-r2 stalled for 6 turns | No AFK stalls |
| V2-5 | **Approve with dictated edits.** When Saad's reply approves and dictates specific edits, apply only those, then `anvil approve <doc> --amended --quote "<his words>"`. The CLI accepts a quote sent after the previous presentation, and records "with the edits he asked for". | CLI `approve`, plan, brainstorm, router | F6: c2 2/3 runs re-asked for approval | One fewer stop round trip |
| V2-6 | **`anvil run` converts POSIX paths on Windows.** `/tmp/...`-style arguments become native paths before the test command starts. The `--quote` text stays untouched. | CLI `results` | F7: 4/14 runs hit `/tmp` failures | No wasted retries |
| V2-7 | **The edit hold lets docs through.** Markdown under `docs/` is never held before approval, since project rules often require decision logs. Code stays held. | CLI `hooks` | F8: c5-A-r1 was denied `docs/decisions.md` twice | Project doc rules met without fights |
| V2-8 | **Docs are edited with Edit or Write only**, never heredocs, `sed` or `cat >>` on topic docs. | router, formats | F9: 6/14 runs; one emptied spec was committed | No broken docs |
| V2-9 | **Lanes keep line endings.** Implementers and the inline builder keep each file's line endings and check `git diff --stat` before reporting. | build prompts, build | F10: 5/14 runs had a CRLF fix round | No line-ending fix rounds |
| V2-10 | **Unstated restrictions are calls.** A rule the request didn't state (an error for a combination, a rejected value) goes under "Calls I made", so the stop catches it. | brainstorm, plan | F11: c3 3/3 | The c3 `brief` miss is surfaced at the stop |
| V2-11 | **Plain hand-off reports.** Lead with the outcome. Say what changed, how it was verified and which calls to check. Ids (S3, T1, C1) go in docs, not chat, unless asked. The topic docs say "you", not "Saad", when addressing him. | router, verify, build | Judge communication 3.14 against 3.81; F13 | Communication ≥ 3.6 |

**Not changed, on purpose:**
- Sizes and stops: the c2 stop is where V1 won.
- The spec and plan formats, and the gates' quote rule.
- Parallel mode stays for wide plans. It wasn't exercised by these fixtures.

## Test strategy

- **Unit tests** in `tests/anvil_cli/`:
  - approve `--amended`: accepts a quote after the previous present when the doc changed; refuses a quote from before it; records "with the edits he asked for";
  - POSIX path conversion: converts `/tmp/x` when `cygpath` exists; leaves `--flag` and relative paths alone; keeps the result key stable between `run` and `fresh`;
  - the hold allows `docs/*.md` and still holds `src/x.py`;
  - `topic start` auto-parks a topic at stage `finish`, and still refuses one at build.
- The skill lint (`test_skills.py`) passes on all skills.
- **The A/B gate:** `abtest` suite `v2`, arm A, 3 runs per case. A blind 4-way judge per replicate (V1, V2, Superpowers, no plugin), and a comparison report against the stored `full` suite.

## Order

1. CLI changes plus tests (V2-3 parking, V2-5, V2-6, V2-7).
2. Skill text (V2-1 to V2-4 and V2-8 to V2-11), then the lint.

4. Run the A/B suite `v2`, judge it 4-way, write `docs/anvil-v2/2026-11-19-v2-results.md`.
5. If a target misses, iterate on that finding only, and rerun the cases it affects.
