# Anvil 0.3.0: stand-up skill, machine rules, repo sync

Date: 2026-11-23. Status: **approved through the answers on 2026-11-23**, building.
Path: spec first, built inline. Mode: **normal change**. No existing skill file
changes.

This replaces the 2026-11-18 stand-up design (commit `c3dc792`, side
branches only), which was agreed but never built. The findings behind this
version are in
[../../standup/2026-11-23-findings.md](../../standup/2026-11-23-findings.md).

## Intent

1. **Stand-up.** "Give me my stand-up", or a pasted stand-up bot prompt, gets
   a draft built from what the user says plus the evidence in the folder the
   skill runs from. The user edits it and says "good to go". The approved
   text is saved to a dated log that feeds the next draft. There is **one
   scope** for now: the current folder. Profiles come in a later release,
   once the skill has been used and measured.
2. **Machine rules on install.** The rules the user sets up on every machine
   (local files, no co-author trailers, a second model only when asked) arrive
   with Anvil from the marketplace, through a SessionStart hook.
3. **Multi-machine sync.** A repo that is worked on from several machines opts
   in with a committed `.claude/rules/remote-sync.md`. That file is the rule,
   and Claude Code loads it natively. At session start, the hook fetches and
   tells Claude whether the repo is behind, diverged, or has unpushed or
   uncommitted work, so the pull happens before any edit.

## Non-goals and anti-goals

- No writes to any tracker, comments included (a connector may be signed in as
  someone else), and no posting to a bot, chat or client.
- No profiles, `profile.md` or kind-specific rules in this release.
- The hook never pulls, commits or pushes. It only reports. Claude acts under
  the repo's rule.
- **Failure:** an invented ticket id, date or duration; raw prompts or file
  contents in a saved file; an answer longer than about four lines; the hook
  slowing down or breaking startup in a repo that hasn't opted in.

## Acceptance lines: stand-up

- **A1 Scope.** The scope is the current folder and everything under it.
  Project rules about stand-ups (`CLAUDE.md`, `.claude/rules/*`) are binding
  and win over the skill's defaults, except for the log location.
- **A1b Log location** (changed 2026-11-23, from `<scope>/standups/`, at the
  user's request, so reports never scatter): every report goes in
  `~/standups/`, whatever the scope. `gather.py` computes the exact paths and
  prints them as `log.dir`, `log.save_report_to` and `log.save_json_to`. The
  skill writes only there. A project rule naming another folder is reported
  to the user as out of date, not followed.
- **A2 Questions.** The default set is Yesterday, Today, Left, Blocked, Other,
  with the wording in `report-format.md`. A project rule that gives other
  wording or another order wins.
- **A3 Evidence.** `gather.py` prints one JSON summary (`schema_version: 1`)
  to a temp file. It covers:
  - repos up to three levels deep;
  - git, per repo with a timeout: the branch, branches touched, commits by the
    authors, and uncommitted and untracked counts plus up to 10 paths;
  - sessions whose `cwd` is inside the scope;
  - non-repo folders, as a changed-file count and a few names;
  - ticket ids;
  - PRs through `gh` when it is available, otherwise `skipped` with the reason.

  Lines it doesn't recognise are skipped without failing.
- **A4 Window.** The window starts at `covered_until` from the newest
  `~/standups/*.json`, with `-2` counted as newer than the plain date. With none, it starts at the start of the previous working
  day (Mon–Fri, local time), so Monday covers Friday and the weekend. It ends
  now.
- **A5 Draft.** Yesterday comes from the user's account first, then evidence,
  one line per ticket. The previous report's Today items with no evidence are
  listed as "planned, not seen". Under the draft: guesses, tracker
  mismatches, and evidence left out on purpose.
- **A6 The user's account wins.** "Today is only X" puts only X under Today.
  Other open tickets go under Left as moved.
- **A7 Left.** Days left are working days to the due date (due today = 0).
  **Late** means past due, or moved and no longer meetable, with the new date.
  **At risk** means it can be met only if a named thing happens. Otherwise
  **on track**. A late ticket still gets a Today line saying what will be done
  on it.
- **A8 Tracker, read only.** A mismatch (a stale due date, or a status behind
  the work) is listed with the field change and a drafted comment for the
  user to make. The skill names no other skill.
- **A9 Unknowns are asked.** A duration, a missing ticket (`XXX-___`) or a
  meeting the evidence can't show is asked, never filled in. Other doesn't
  repeat Yesterday. Work with no ticket is left out when the tracker is in
  use.
- **A10 Save on approval only.** On clear approval:
  - `~/standups/YYYY-MM-DD.md` (or `-2` for a second report that day) holds
    the approved text split by question, plus "Sources checked";
  - `YYYY-MM-DD.json` holds `scope`, `covered_from`, `covered_until`, tickets
    (`id`, `status`, `days_left`), Today items and open blockers.

  A first run with only hand-written `.md` reports seeds carry-over from the
  newest one.
- **A11 Edits after posting.** A change after posting updates that day's
  files: the final "As posted" text plus a "Fixes" note with the reason.
- **A12 Reply.** After saving, the reply gives one paste-ready block per
  question (bold header, `•` bullets, one line each, no file paths or
  jargon) and the saved file's path.
- **A13 Leak guard.** A session whose `cwd` is outside the scope contributes
  only file-level facts for files it edited inside the scope. It never
  contributes its title or prompts. Saved files hold only approved text and
  the A10 fields.
- **A14 Generic.** No real client, team, person, channel or tracker workspace
  appears in the skill files. Tools (a tracker connector or CLI, `gh`,
  Python) are discovered at run time, and the skill asks before installing.

Added 2026-11-23 from the user's stand-up chats in the team folder (20 and 23
Nov) and the Chunker repo (18 and 19 Nov):

- **A15 One question at a time.** When the user pastes one bot question, the
  skill answers only that one, and treats the bot's quoted previous report as
  carry-over.
- **A16 Record what was posted.** The pasted posted text is saved verbatim.
  Then it is checked, and the skill lists suggested edits for anything a
  reviewer would send back (a late ticket with only "late" under Today, a
  stale tracker due date, an unconfirmed id), with the comment text to paste.
  After a reviewer's fix, it also drafts a one-line reply.
- **A17 Confirmed ids only.** No ticket id goes into the draft unless this
  run's tracker read confirmed it. Tracker changes and clean-ups asked for in
  the same message wait until the stand-up is done, and happen only on the
  user's go-ahead.
- **A18 Voice.** The report is in the user's voice, about the user's work.
  Others are named only when they need to act, when the work waits on them,
  or when the user named them. When the user says the work isn't in the
  folders, the skill doesn't go looking.

Added 2026-11-23, after the user explained why they paste the bot's Yesterday
question ("so it knew where we left off"), and asked for the chat to be read
directly:

- **A19 Where we left off.** Yesterday starts from the previous report's
  Today list (the log, the chat, or the bot's quoted text). Each item gets
  what happened to it, then unplanned ticketed work is added.
- **A20 Today is asked.** If the user hasn't said, the skill shows the open
  tickets (late, then by due date, then by priority, plus carry-over),
  recommends a list, and asks one question.
- **A21 Chat, own account only.** If a chat connector is available, the skill
  first checks that it is signed in as the user. If so, it reads the bot's
  questions, the last posted report with its thread, and reviewer feedback,
  read-only. If not, it doesn't read at all and tells the user. *Why:* on
  2026-11-23 the attached Slack connector turned out to be a teammate's
  account, the same as the Linear one.

- **A22 Gaps** (2026-11-23, the user: pasting yesterday's question "was just
  necessary for some cases, like if I missed some stand-ups"). `gather.py`
  prints `log.latest_date` and `log.missed_working_days`. With no gap, the
  log is the baseline and nothing is asked for. With a gap, the skill says
  so. It takes the newest baseline from the chat, a paste or the user. It
  asks once for the bot's previous-report text only when nothing newer than
  the log exists. Otherwise it drafts over the whole gap ("since <date>") and
  asks about days with no evidence.

Added 2026-11-23, after the user connected their own read-only chat account
and asked the skill to read the stand-up channel and pick up tasks and
instructions from other people:

- **A23 Chat reading.** On the user's own chat account, and since the window
  start, the skill reads the stand-up channel: the bot's questions, the
  user's last report and its thread, and messages mentioning or replying to
  the user. It also reads direct and group messages to the user and mentions
  in other channels, by search, not by scrolling channels. If the user's
  account isn't the one attached, nothing is read.
- **A24 Asks for you.** Requests from people (not bots) are listed under the
  draft. Each has who, when, a paraphrase, a link, replied or not, the
  matching ticket, and one suggested path: add to Today, new ticket (drafted),
  update a ticket, reply (drafted), correct a sent message (drafted), or
  nothing to do. Open asks feed the Today recommendation.
- **A25 Still read-only.** The skill never sends, edits or reacts in chat,
  and never writes to the tracker. The ticket drafts and updates the user
  picks are offered as a separate step after approval. DM text isn't copied
  into the answers or the saved report. `asks` in the JSON holds one-line
  summaries only, and carries them to the next report.

## Acceptance lines: hook and sync

- **B1** Every session (`startup`, `clear`, `compact`) gets the machine rules
  from `hooks/machine-rules.md` as additional context, in any folder,
  including folders that aren't repos.
- **B2** In a git repo whose top level has `.claude/rules/remote-sync.md`, the
  hook runs `git fetch` (capped at about 5 seconds) and reports the branch,
  ahead/behind, the uncommitted count, and "fetch failed" when it did. If the
  repo is behind or diverged, it says to pull, or to stop and tell the user,
  before editing.
- **B3** In a repo without the file, or in a non-repo folder, there is no git
  call beyond one `rev-parse`, and no sync section.
- **B4** The output is valid JSON. With no bash or no git on the machine, it
  exits 0 with the rules only. It never prints errors at startup.
- **B5** The hook works on Windows (Git Bash, through the `run-hook.cmd`
  polyglot), on macOS and on Linux.
- **B6** This repo and the other 7 repos under `Mine/` carry a committed
  `.claude/rules/remote-sync.md`. Their `CLAUDE.md` "Remote sync" section
  moves into it, so there's one copy. Each repo's diff is shown and approved
  before commit and push.

## gather.py contract

```
gather.py --root DIR [--since ISO] [--until ISO] [--author NAME_OR_EMAIL ...]
          [--projects-dir DIR] [--depth 3] [--out FILE]
```

Keys: `schema_version`, `root`, `window{since,until}`, `repos[]`
(`path`, `branch`, `branches_touched`, `commits[{sha,date,subject}]`,
`dirty{modified,untracked,paths}`, `error`), `folders[]` (`path`, `changed`,
`names`), `sessions[]`, `ticket_ids[]`, `prs{status,items}` and `notes[]`.

Each session carries `id`, `repo`, `branch`, `first`, `last`,
`active_minutes` (gaps over 30 minutes don't count), `scope`
(`inside`/`files-only`) and `files_edited`. An `inside` session also carries
`title` and up to 5 prompts of at most 150 characters each.

Session files are pre-filtered by mtime. The script skips `node_modules`,
`.venv`, `venv`, `dist`, `build`, `graphify-out`, `.git` and `standups`. Each
git call has a 15-second timeout. Past about 40 KB of output, the oldest
sessions' prompts are dropped first.

## Tests (all **keep**)

- **`gather.py`:**
  - Monday with no log gives a window from Friday 00:00 local, and a log's
    `covered_until` is used when present. Guards A4.
  - A session inside the scope is `inside` with its title. A session outside
    it that edited a file inside is `files-only`, with no title or prompts. A
    session that edited nothing inside is absent. Guards A13.
  - Malformed lines are skipped, and gaps over 30 minutes aren't counted.
    Guards A3.
  - In a temp git repo, the author's commit in the window is listed, another
    author's isn't, and an untracked file is counted. Guards A3.
  - With no `gh`, `prs.status` is `skipped`. Guards A3.
- **Hook:**
  - A non-repo folder gets the rules only, as valid JSON. Guards B1, B3, B4.
  - A clone one commit behind its bare remote, with the rule file, reports
    "behind 1". Guards B2.
  - The same clone without the rule file has no sync section. Guards B3.
